# Firmware session protocol 2 (development)

All session requests require administrator Basic authentication and X-Wordclock-Action: firmware-update. Use GET /api/system/firmware for preflight. POST firmware/authorize with size, sha256, confirm=INSTALL and 512 hex signature returns a single-use ticket (60 s). POST firmware/start with ticket as token and confirm=INSTALL returns a separate session token and chunkSize=512 (client must use the returned size). PUT firmware/chunk with token and offset, raw bytes as text/plain body. GET firmware/status reports offset, size, verified and memory. POST firmware/verify checks complete SHA-256. POST firmware/activate with token and confirm=INSTALL is the sole commit path. POST firmware/cancel discards staging. Paths are relative to /api/system/. Session inactivity limit 60 s; loss of Wi-Fi also cancels. Invalid offsets do not advance the session. Last 256 bytes retained until verified activation; incomplete Update.end(false) discards staging. Legacy multipart install returns 410; diagnostic multipart routes removed. Old web clients require an interface update. Never upload a whole LittleFS image to migrate the interface.

Local HTTP and ArduinoOTA are development-only security limitations. Memory thresholds are provisional. Full transfer not yet hardware validated. Version 20.8.2 removes the additional application-level String copy by taking a const reference and reduces firmware blocks to 512 bytes. The framework still buffers and copies the HTTP body; this is a controlled mitigation, not direct TCP streaming. Web update block size is unchanged. Run tools/test_firmware_session.py with a signed image to exercise rejection and verification without activation. Do not publish firmware until hardware testing and credential provisioning are complete.
