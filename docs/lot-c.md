# Lot C — animations (3.3.0-dev)

- Existing theme renderer and rear effects are retained. New front behavior uses the existing LED frame after transition snapshots, before face/global brightness and night/status processing. No additional frame array.
- Global enable disables decorative theme animations/transitions and new effects (system indicators remain). New features are opt-in: 5-minute transition, spatial rainbow/chase, hourly palette, hourly or noon/midnight cuckoo. New effects are suppressed at night, during theme preview, when time is invalid, during web maintenance and when the clock/front is off. Existing theme effects retain their prior night semantics.
- Cuckoo starts only on an observed minute 59 -> 00 with changed hour and seconds 0..5; no replay of missed events. A chime takes precedence over a word transition. Word transition triggers at five-minute bucket changes. Minute dots are not modified by overlays. Existing theme and brightness transitions remain separate. Manual clock corrections at a boundary may trigger an event; a full scheduler is planned for lot D.
- One optional packed `frontBehavior` field in existing settings version 8, default when absent; read-back verification and reset support. Old firmware ignores it and may drop it if it rewrites settings. Theme JSON format unchanged. New web with old firmware displays unavailable settings; rollback to old web does not remove the firmware's saved behaviors.
- GET /api/animations (read-only); POST same endpoint with `X-Wordclock-Action: animations` and all seven numeric fields plus spatialSpeed (enabled, hourlyColor, transition, chime, spatial, spatialSpeed, intensity, duration). Duration 1000..5000 ms step 100; intensity/speed 0..100. POST /api/animations/test with same header and kind 1..6. No persistence of preview. Updates and maintenance reject actions. As with ordinary local settings, this assumes a trusted local network.
- Browser preview remains a theme approximation; use the physical test button for transient effects, save settings for permanent effects. New GET is lazy on opening settings.
- `python tools/validate.py` runs native C++ algorithm tests when a host compiler is available; optional `--host` checks new API and reports failing HTTP endpoint names. Native math tests do not substitute for ESP8266 compile or physical rendering. Prior 18/20 HTTP result, offline AP and physical update interruptions remain outstanding.
